# v0.1.1 Reliability Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v0.1.1 with single-instance and data locking, crash-recovery autosave, non-blocking character-library scans and chat loads, and bounded transport/parser behavior, without changing the 19 critical v0.1 features.

**Architecture:** Keep `libstcore` GTK-free. Add advisory `flock` locks and a chat journal in core, then move the two blocking UI read paths (library scan, chat load) to worker threads that marshal results through `Glib::Dispatcher`. Harden the HTTP/SSE and PNG boundaries last, and verify everything under ASan/UBSan, Xvfb, and Alpine musl.

**Tech Stack:** C++17, gtkmm-3.0, libcurl, ncursesw, GNU Make, Xvfb, Docker, Python 3.

**Spec:** `docs/superpowers/specs/2026-11-01-sillytavern-cpp-port-design.md`

**Baseline:** `b4ee327` on `port/v0.1`; working tree clean before Task 1.

## Global Constraints

- v0.1.1 keeps all 19 critical v0.1 features ported; P09 and P10 move from `planned` to `ported` with `target: "0.1.1"`.
- `src/core/` stays GTK-free. Worker threads never touch GTK widgets; only `Glib::Dispatcher` handlers do.
- Startup character scans and character-switch/chat-selector loads run off the GTK main thread. Explicit import/delete writes may stay synchronous and must be documented.
- Chat writes stay atomic (`temp` + `fsync` + `rename`), and a failed save must leave the previous chat file intact.
- The lock and journal locations stay under the XDG data root. Never write into `SillyTavern/`.
- `settings.json` remains capped at 1 MiB; character cards, chats, and journal files at 64 MiB.
- Build stays warning-free with `-Wall -Wextra -Wpedantic`.
- One descriptive commit per task. Never delete a plan in `docs/plans/`.
- The existing host and Alpine gates must still pass, plus the new sanitizer target.

## Review Focus

1. A second app instance or a second writer must not corrupt a chat; the second save must fail cleanly and leave the first writer's state intact.
2. A process killed mid-stream must leave a recoverable draft; the next load must restore the partial assistant exactly once and clear the draft.
3. Switching characters or chats while a load is in flight must never install the old result over the new selection.
4. A large character library or a 64 MiB chat must not freeze the GTK main loop.
5. Malformed SSE or PNG input — CR-only framing, mid-UTF-8 splits, truncations, and oversized HTTP bodies — must produce an exact result or a bounded error, never a crash or unbounded memory.

## Self-Review

**Spec coverage:** P09 and P10 are implemented and reclassified as v0.1.1 features. The design's "blocking file I/O off the GTK thread" requirement is met for startup library scans and chat loads; explicit small writes remain synchronous and documented.
