# v0.2 Chat Depth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the native port feel like SillyTavern for everyday chat: alternate responses (swipes), branching and bookmarks, author's note, Markdown rendering, and chat backups.

**Architecture:** Extend the existing `ChatSession`/`ChatStore` model first, always inside the SillyTavern-compatible JSONL shape (`swipes`/`swipe_id` in the message object, extra fields preserved). Add GTK-free `markdown` and `backup` modules so they are unit-testable, then wire thin UI layers in `ChatView` and `MainWindow`. Registry entries move to `ported` with `target: "0.2"` only in the final release task.

**Tech Stack:** C++17, gtkmm-3.0, libcurl, ncursesw, GNU Make, Xvfb, Docker, Python 3.

**Spec:** `docs/superpowers/specs/2026-11-01-sillytavern-cpp-port-design.md`

**Baseline:** the v0.1.2 release commit on `port/v0.1` (plan `09-v0.1.2-reliability-cleanup.md` must be complete first); working tree clean before Task 1.

## Global Constraints

- Chat files stay SillyTavern-compatible JSONL: one metadata object, then one object per message; unknown fields round-trip untouched.
- `src/core/` stays GTK-free. Worker threads never touch GTK widgets; only `Glib::Dispatcher` handlers do.
- No new third-party dependencies. Markdown rendering is a hand-written subset; no WebKit, no HTML engine.
- Chat writes stay atomic; per-chat locking and the draft journal are preserved.
- Sizes stay capped: `settings.json` 1 MiB, cards and chats 64 MiB, drafts 16 MiB, one backup tree 512 MiB with 10 kept.
- Backup and journal paths stay under the XDG data root. Never write into `SillyTavern/`.
- Build stays warning-free with `-Wall -Wextra -Wpedantic`; both gates and the sanitizer target must pass.
- One descriptive commit per task. Never delete a plan in `docs/plans/`.
- A feature moves to `ported` only in Task 10, after its behavior is implemented and tested.

## Review Focus

1. Swiping never loses a previous reply: `swipes` and `swipe_id` stay consistent with `mes` through save/load, edit, delete, and a crash.
2. Branching copies exactly the prefix through the chosen message and never mutates or truncates the source chat.
3. Author's note appears exactly once at the intended depth, including when the depth exceeds the history length or the note is enabled with empty text.
4. Markdown input can never inject HTML or break Pango parsing: `<`, `&`, unclosed fences, and pathological nesting render literally or safely.
5. Backup and restore are safe on failure: a failed restore leaves every existing chat byte-identical, and backup paths never escape `chats/.backups`.

### Task 8: Chat backup and restore core

**Files:**
- Create: `SillyTavern_port/src/core/backup.h`, `SillyTavern_port/src/core/backup.cpp`, `SillyTavern_port/tests/test_backup.cpp`

**Interfaces:**
- Produces:
```cpp
struct BackupEntry {
    std::string id;
    std::filesystem::path path;
    std::size_t chats = 0;
    std::uintmax_t bytes = 0;
    std::string created;
};

class BackupManager {
public:
    explicit BackupManager(std::filesystem::path chats_root);
    std::string create(const std::string& label = {});
    std::vector<BackupEntry> list() const;
    void restore(const std::string& id) const;
    void prune(std::size_t keep = 10);
};
```
- Layout: `chats/.backups/<YYYY-MM-DD_HH-MM-SS>[-<label>]/` containing `manifest.json` (`id`, `created`, `chats`, `bytes`) and `<character>/<file>.jsonl` copies.
- `create` refuses with `std::runtime_error("backup exceeds 512 MiB limit")` when the copied total would exceed 512 MiB, and after a successful copy calls `prune(10)`.
- `restore` reads each backed-up chat with `read_file_limited` (64 MiB) and writes it back through `write_file_atomic`; a chat present on disk but absent from the backup is left untouched. Any error aborts before the first write (validate every file first).
- `list` skips directories without a readable `manifest.json` and sorts newest first.
