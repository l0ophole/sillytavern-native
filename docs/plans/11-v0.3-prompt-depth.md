# v0.3 Prompt Depth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make prompts feel like SillyTavern for power users: lore injection (World Info), personas, instruct formatting and context templates, an ordered prompt manager with presets, and advanced sampling with regex/variable rewriting.

**Architecture:** Extend the existing `build_prompt_parts` assembly point first, always GTK-free and inside SillyTavern-compatible JSON shapes (`settings.json` unknown keys preserved, `worldinfo/*.json` and `presets/*.json` as plain JSON). Add GTK-free `world_info`, `persona`, and `prompt_manager` modules so they are unit-testable, extend `Settings`/`Sampling`/`prompt` for instruct/templates/regex/variables, then wire thin UI layers in `SettingsDialog` and `MainWindow`. Registry entries move to `ported` with `target: "0.3"` only in the final release task.

**Tech Stack:** C++17, gtkmm-3.0, libcurl, ncursesw, GNU Make, Xvfb, Docker, Python 3. No new third-party dependencies; regex uses `std::regex` with explicit length caps.

**Spec:** `docs/superpowers/specs/2026-11-01-sillytavern-cpp-port-design.md`

**Baseline:** the v0.2.0 release merge commit on `main`/`port/v0.1` (`c48bf49`); working tree clean before Task 1. Work on branch `port/v0.1`.

## Global Constraints

- `settings.json`, lorebook and preset JSON stay tolerant: unknown keys round-trip untouched, 1 MiB cap on `settings.json`, 64 MiB cap on cards/chats, 16 MiB cap on lorebooks and presets.
- `src/core/` stays GTK-free. Worker threads never touch GTK widgets; only `Glib::Dispatcher` handlers do.
- No new third-party dependencies. Hand-written subsets only; no WebKit, no HTML engine.
- Prompt injection is bounded: World Info recursion depth max 5, at most 32 triggered entries, total injected content max 32768 bytes, single entry content truncated to 4096 bytes.
- Regex is bounded: pattern length max 512 bytes, replacement max 4096 bytes, at most 16 rules, pattern must compile with `std::regex` or the rule is skipped; `std::regex_error` is caught and the rule treated as literal.
- Token budgeting is respected: World Info and prompt-manager sections go through `fit_history`/`estimate_tokens`; over-budget history still trims oldest first.
- All writes stay under the XDG data root and are atomic (`write_file_atomic`). Lorebook/preset filenames are sanitized via `sanitize_filename`; imports never escape `worldinfo/` or `presets/`.
- Build stays warning-free with `-Wall -Wextra -Wpedantic`; both gates and the sanitizer target must pass.
- One descriptive commit per task. Never delete a plan in `docs/plans/`.
- A feature moves to `ported` only in Task 10, after its behavior is implemented and tested.

## Review Focus

1. World Info never injects unbounded lore: only enabled entries whose key appears (case-insensitive) in history or the current user message trigger; recursion is capped, duplicates are removed, budgets are enforced, and no entry triggers more than once per prompt build.
2. Persona selection never breaks `{{user}}`: the active persona description is injected exactly once and `{{user}}` still expands to the persona name; an empty or missing persona leaves the prompt unchanged.
3. Instruct mode and context templates preserve prior prompt order: a chat saved before v0.3 loads and sends with the same leading/history/trailing structure when the new settings are at defaults.
4. Prompt-manager enable/disable, sampler fields, regex, and variables cannot silently drop history or corrupt the request: disabled sections are absent, regex operates on display copies only, variables expand after other macros, and the OpenAI payload remains valid JSON.
5. Lorebook and preset import/export are safe on failure: malformed JSON throws with context, paths never escape the data root, existing files are never overwritten without explicit overwrite, and a failed import leaves the store byte-identical.

**Interfaces:**
- Produces in `world_info.h`:
```cpp
struct WorldInfoEntry {
    std::string key;       // comma-separated keywords, e.g. "dragon, wyrm"
    std::string comment;
    std::string content;
    bool enabled = true;
    int position = 0;      // lower injects first
    int depth = 0;         // reserved, clamped 0..100
};
struct WorldInfoBook {
    std::string name;
    std::vector<WorldInfoEntry> entries;
    static WorldInfoBook from_json(const Json& value);
    Json to_json() const;
};
std::vector<WorldInfoEntry> triggered_entries(const WorldInfoBook& book,
                                              const std::vector<std::string>& texts,
                                              int max_recursion = 5);
```
- `WorldInfoBook::from_json` reads ST shape `{"name","entries":[{"key","comment","content","disable","position","depth"}]}` or a bare array of entries; unknown fields are preserved in `entries` via `Json` capture only for round-trip within `content/key/comment` (extra per-entry fields ignored but not stored). `to_json` writes the `entries` array with `disable = !enabled`.
- `triggered_entries`: case-insensitive substring match of any comma-separated key against any text; enabled only; sorted by `position` then `key`; deduplicated by `key+content`; recursion: triggered entries' `content` is re-scanned up to `max_recursion` times (capped at 5, hard-capped at 5 regardless of caller); at most 32 entries; each `content` truncated to 4096 bytes; total injected bytes capped at 32768 (stop adding once exceeded).
- Produces on `Settings`: `bool world_info_enabled = false; std::string world_info_book = "lorebook";` with tolerant `to_json`/`from_json` and `validate()` clamping `world_info_book` via `sanitize_filename` (empty becomes `"lorebook"`).
- `build_prompt_parts(card, settings, history)` gains world-info injection: when enabled, collect history texts (`mes` of all messages plus the last user message if present) and call `triggered_entries` with an empty book if the book file is unreadable; inject triggered contents as one `system` message `"World Info:\n" + joined("\n\n")` appended to `leading_system` (after character system text, before history). No injection when disabled, empty, or no triggers.
