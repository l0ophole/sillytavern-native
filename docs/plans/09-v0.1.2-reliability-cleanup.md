# v0.1.2 Reliability Cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the nine non-blocking defects and test gaps that the v0.1.1 whole-branch review deferred, without adding user-facing features or changing the feature registry's ported set.

**Architecture:** Keep `libstcore` GTK-free. Extract the draft-save throttling policy into a small pure class so it can be tested without GTK, make `ChatStore` own the whole draft lifecycle (write cap, remove, rename, existence), extend `ChatDraft` with a regeneration mode, and fix the two remaining async/parser rough edges. Finish by teaching the host gate to assert the warning-free build it already claims.

**Tech Stack:** C++17, gtkmm-3.0, libcurl, ncursesw, GNU Make, Xvfb, Docker, Python 3.

**Spec:** `docs/superpowers/specs/2026-11-01-sillytavern-cpp-port-design.md`

**Baseline:** `e1f9096` on `port/v0.1` (tag `v0.1.1`); working tree clean before Task 1.

## Global Constraints

- No new user-facing features. The registry stays at 21 ported / 84 planned, targets 19 `0.1` and 2 `0.1.1`; no feature moves to `ported`.
- `src/core/` stays GTK-free. Worker threads never touch GTK widgets; only `Glib::Dispatcher` handlers do.
- Chat writes stay atomic (`temp` + `fsync` + `rename`), and a failed save leaves the previous file intact. Per-chat locking is preserved.
- Lock and journal locations stay under the XDG data root. Never write into `SillyTavern/`.
- `settings.json` stays capped at 1 MiB; character cards and chats at 64 MiB; compact drafts at 16 MiB.
- Build stays warning-free with `-Wall -Wextra -Wpedantic`, and the host gate gains an assertion for that.
- One descriptive commit per task. Never delete a plan in `docs/plans/`.
- Both gates (`tests/verify_v01.sh`, `tests/alpine_build.sh`) must pass.

## Review Focus

1. A draft write that fails must not be recorded as saved; a persistently failing journal retries at a bounded rate that backs off, never once per chunk.
2. Deleting or renaming a chat never leaves a draft that can resurrect deleted content, and a draft-only name never collides with a newly created chat file.
3. A process killed while regenerating recovers the partial reply by replacing the previous reply exactly once — never duplicating it, never appending it twice.
4. A character scan that fails is reported as a failure, not as an empty library, and `is_scanning()` can never stay true after the last scan finishes.
5. A long unterminated SSE line split across many feeds stays bounded in memory and does not re-scan bytes already examined.

### Task 3: Recoverable drafts for regeneration

**Files:**
- Modify: `SillyTavern_port/src/core/chat_store.h`, `SillyTavern_port/src/core/chat_store.cpp`, `SillyTavern_port/src/core/chat_session.cpp`, `SillyTavern_port/src/ui/chat_view.h`, `SillyTavern_port/src/ui/chat_view.cpp`
- Test: `SillyTavern_port/tests/test_chat_store.cpp`, `SillyTavern_port/tests/test_chat_session.cpp`

**Interfaces:**
- Produces: `bool st::ChatDraft::replace_last = false;` persisted as the optional JSON field `"replace_last"`; a missing field loads as `false` for backward compatibility.
- Produces: `ChatSession::recover_draft` gains the rule below.
- Consumes: `ChatView::base_messages_`, `ChatView::maybe_save_draft`, `ChatView::on_regenerate`.

Recovery rule:
- `replace_last == false`: unchanged — require `draft.base_messages == chat_.messages.size()`.
- `replace_last == true`: require `chat_.messages.size() == draft.base_messages + 1`, a non-empty draft, and that the last message is an assistant message; then set that message's `mes` to `draft.text` (and its `send_date` to `draft.send_date` when non-empty) and return `true`. Never append a second message.
